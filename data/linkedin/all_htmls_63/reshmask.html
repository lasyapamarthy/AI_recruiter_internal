It’s useful for tracking when elements are added, removed, or altered on a web page. This is particularly helpful in dynamic web applications where content can be updated without reloading the page, such as with AJAX or single-page applications (SPAs). hashtag#HowMutationObserver Works A Mutation Observer monitors the DOM and reports when specified changes occur. You set it up by creating a new instance, providing a callback function to handle any changes it detects, and configuring it to watch for specific types of changes. hashtag#KeyFeatures Efficient Monitoring: Instead of using repetitive DOM polling (like setInterval), a MutationObserver only triggers when actual changes occur, making it more efficient. Before Promises, async operation's were handled by callbacks, which would result in Callback hell and Inversion control. Inversion control is overcome by promises and for callback hell we can use promise chaining. A promise is an object that represents an eventual completion/failure of async operation. And a promise can be one of three states. Pending, Fulfilled and Reject. A promise is an empty object which is assigned undefined in pending state. As soon as a promise is fulfilled or rejected it updates empty object with data. A remarkable constraint of Promises is, a promise is resolved only once and immutable. In callbacks we pass call back function as an argument to another function which causes inversion of control, but in promises we attach call back functions to the promise object. Once the promise object is filled with data it will certainly calls the call back function. By this we will have the control of our program with us. the execution context of Promises is like, When a Promise is created and the asynchronous operation is started, the code after the Promise creation continues to execute synchronously. When the Promise is resolved or rejected, the attached callback function is added to the microtask queue. The microtask queue is processed after the current task has been completed but before the next task is processed from the task queue. This means that any code that follows the creation of the Promise will execute before the callback function attached to the Promise is executed. Chaining Promise: Sometimes you need to do several things one after another like load some data, process it and then display it. With promise you can do this by chaining the methods. So promise chaining is the practice of sequentially executing asynchronous operation using multiple then() calls on a promise. An error can also be created using new Error('error message'). .catch() which is used to attach a failure callback function that handles any error that pops up during the execution of promise chain. .catch() only handles error of .then() that are present above it. If there is any .then() below it, catch will not handle any error for that, also that ,then will get executed no matter what. It can be useful in a way if we want to catch error for a particular portion of a chain. We can have multiple catch() based on requirement and then a general catch at the end. Always remember to return a value in the promise chain for the next .then to use . hashtag#promise- one of the significant concepts of JavaScript.
