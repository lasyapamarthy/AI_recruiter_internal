Think of it like a function that takes a component and adds extra functionality to it, then returns the new enhanced component. 𝗛𝗢𝗖𝘀 are not part of React’s core API, but they are a powerful pattern widely used in real-world applications. One common use of 𝗛𝗢𝗖𝘀 is to handle data fetching or logic that you don’t want to repeat in multiple components. Let’s understand this with the provided code. The UserInfo component is a simple component that displays user information like name, age, country, and a list of books. It expects a user object to be passed as a prop. If the user is not available yet, it shows a “Loading...” message. This component only focuses on presenting the data and doesn’t care about how or where the data comes from. The logic for fetching the user data is handled in a separate function called withUser. This is the HOC. It takes two arguments: a component (WrappedComponent) and a userId. Inside it, it fetches user data from an API using the user ID, and once the data is loaded, it passes the user data as a prop to the original component. This keeps the UserInfo component clean and focused only on displaying data, while the data fetching logic is reused and separated. Finally, in the App component, the HOC is used by calling withUser(UserInfo, userId), creating a new component called UserInfoWithLoader. This enhanced component knows how to fetch the user data and then render the UserInfo component with that data.
