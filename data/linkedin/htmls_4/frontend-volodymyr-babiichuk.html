Але в реальності є неочевидні обмеження, які можуть викликати баги. 🔷 Обмеження обсягу Зазвичай доступно до 5–10MB для кожного origin. Якщо його перевищити, setItem() викине помилку (QuotaExceededError) при спробі зберегти нові дані. Без try/catch додаток викине необроблену помилку. 📌 Краще не зберігати великі об’єкти та слідкувати за обсягом. Також корисно мати утиліту, яка підраховує сумарний обсяг localStorage. Це допомагає виявити ризики ще на етапі розробки. У випадку помилки у catch можна видалити непотрібні ключі або показати користувачеві повідомлення про очищення. 🔷 Синхронність Операції з localStorage синхронні, тому при записі великих обсягів можуть блокувати головний потік і впливати на продуктивність. 📌 Для великих обсягів краще використовувати IndexedDB або зберігати дані на сервері через API 🔷 Race condition між вкладками Хоча localStorage є синхронним API в межах одного потоку, race condition часто виникає між вкладками, оскільки вони мають спільний доступ до сховища і не блокують одна одну. Якщо кілька вкладок працюють з тими самими ключами і перед записом є асинхронна логіка, наприклад fetch, то одна вкладка може перезаписати нове значення старим. 📌 У результаті користувач бачить старі значення, навіть якщо щойно зберіг інші. Щоб цього уникнути: записуйте зміни у localStorage одразу, до будь-яких асинхронних дій. Або додавайте timestamp, щоб не перезаписати новіші дані. Також можна слухати подію storage в інших вкладках. Вона не усуває race condition, але дозволяє оновити інтерфейс, якщо дані змінилися в іншій вкладці. localStorage може здаватися елементарним API, але на практиці має особливості, які легко пропустити. Синтаксис: 🍭 let promise = new Promise(function(resolve, reject) { // код, що виконує асинхронну операцію }); Стани: 🍭 Pending (очікування) - початковий стан. 🍭 Fulfilled (виконано) - операція завершена успішно. 🍭 Rejected (відхилено) - операція завершена з помилкою. (Властивості state і result є внутрішніми для об'єкта Promise і не доступні напряму, на картинках нижче прикріплено як вони працюють) Методи екземпляра (instance methods) 🍧 Метод екземпляра - це метод, який викликається на конкретному об'єкті Promise. 🍭 .then(onFulfilled, onRejected) - обробляє успішне виконання або помилку. 🍭.catch(onRejected) - спеціалізований метод для обробки помилок. 🍭 .finally(onFinally) - виконується в будь-якому випадку. Статичні методи (static methods) 🍧 Статичний метод - це метод, який викликається на самому конструкторі Promise, а не на його екземплярі. 🍭 Promise.resolve(value) - створює виконаний Promise. 🍭 Promise.reject(reason) - створює відхилений Promise. 🍭 Promise.all(iterable) - чекає виконання всіх або першої помилки. 🍭 Promise.allSettled(iterable) - чекає завершення всіх незалежно від результату. 🍭 Promise.race(iterable) - чекає першого завершеного. 🍭 Promise.any(iterable) - чекає першого успішного. Async/await 🍭 async - ключове слово для оголошення асинхронної функції: - Автоматично перетворює функцію на Promise. - Дозволяє використовувати await всередині. - Завжди повертає Promise. 🍭 await: може використовуватись тільки в async-функціях - Призупиняє виконання функції до завершення Promise. - Повертає результат виконаного Promise. - Якщо Promise відхилено, генерує помилку. Коли використовувати/для чого потрібен 🍭 Для роботи з асинхронними операціями. 🍭 Для уникнення "callback hell". 🍭 Для кращої організації асинхронного коду. 🍭 Для паралельного виконання операцій. Ланцюжки Promise (Chaining) 🍧 Ланцюжок Promise - це послідовність асинхронних операцій, де кожна наступна операція починається після успішного завершення попередньої. 🍭 Кожен .then() повертає новий Promise. 🍭 Значення, повернене з .then(), стає аргументом для наступного .then() 🍭 Якщо повертається звичайне значення - воно автоматично обертається в Promise. 🍭 Якщо повертається Promise - наступний .then() чекає його завершення. somePromise .then(handleFirst) .then(handleSecond) .then(handleThird) .catch(handleAnyError) .finally(cleanUp); Нескасованість Promise 🍭 Нескасованість - фундаментальна властивість Promise, яка означає, що операція не може бути зупинена після її запуску.
