Reentrancy is one of the most dangerous and common vulnerabilities in smart contracts. It occurs when an external contract call can re-enter the calling contract before the first execution is complete, potentially executing malicious code (function on line 25 in Attack.sol) while the contract is in an inconsistent state. Every time etherStore.withdrawFunds() is called, the payable callback is triggered calling withdrawFunds again. Preventative Techniques - use the built-in transfer function when sending ether to external contracts.
